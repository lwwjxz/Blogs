
# 单元测试
## 需求
补充单测
### 步骤
1. 先跟git仓库的master分支比较全面识别所有有修改的类文件。
2. 找出需要补充/修改单测的类。
   1. DO/DTO/Requst/PO/Entry/Response和其他只有简单get，set方法的简单类不要补充单测
   2. 枚举类不需要补充单测
   3. 检查这些类是否已有对应的测试类，对于已有测试类的类，对应修改改过的代码补充或修改单测，对于没有测试类的类需要新建单测。
   3. 确保创建完整的测试类
3. 补充单测，要求新增and修改代码的行覆盖率要大于70%，分母为变更的总行数(包括新增和修改)，分子为单元测试覆的行数
4. 检查 
   1.  所有代码都能成功编译   
   2.  单元测试能够正常运行并通过    
   3.  修改代码行覆盖率是否大于70%    
5. 检查不通过继续修复知道通过检查
6. 将新增的文件放到暂存区(git add) 
7.  #不要修改被测代码#
